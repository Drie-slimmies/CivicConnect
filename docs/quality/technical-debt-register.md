# Technical Debt Register

Shortcuts and gaps the team has knowingly accepted, so they are tracked and not forgotten. Added in M3 (13 October 2026) with the authentication branch; each later slice adds its own rows (TD-10 to TD-14 with the staff slice and TD-15 with the quality strategy, 16 October 2026). Status is Open unless stated.

| ID | Debt item | Where | Why accepted now | Consequence if left | Repay when / how | Linked |
|---|---|---|---|---|---|---|
| TD-01 | No login rate limiting or account lockout | `app/api/auth/login/route.ts` | M3 scope and time; the password hash is deliberately slow (scrypt) | Someone can guess passwords without being slowed down | Before real users: add a per-email and per-address attempt limit | R-13 |
| TD-02 | No revocation of a single session | `lib/auth/session.ts` (stateless signed cookie, ADR-06) | A session table would add a migration and a database read on every request | A stolen cookie works for up to 8 hours; only rotating `SESSION_SECRET` signs everyone out | If real data is held: move to database-backed sessions or add a token version per user | R-13, ADR-06 |
| TD-03 | Password reset and email verification not built | Sign-up and sign-in flow | Deferred scope (CR-009) | A forgotten password needs a manual database change; accounts can be made with an email the person does not own | When email sending exists (notifications are also deferred) | CR-009, FR-001 |
| TD-04 | `admin` role exists in the schema but is not used | `lib/db/schema.ts`, `lib/auth/guard.ts` | No admin screen in M3 | Unused role may suggest a feature that does not exist | Build the admin screen or remove the role | CR-009 |
| TD-05 | API tests mock the database | `tests/api/auth/*.test.ts`, `tests/api/requests/*.test.ts`, `tests/unit/requests/service.test.ts` | Tests must run in CI without a database or secrets | SQL, constraints, the unique-email index, the request and audit transactions, the version check and the lookup indexes are only checked by hand on Neon | Add integration tests against a test database (for example a Neon branch or a local Postgres); planned as A4, E1 and E2 in the [quality strategy](quality-strategy.md), run before release | R-13, R-10, M3 integration evidence |
| TD-06 | No automated test for `getCurrentUser`, `readSession`, sign-out or the sign-in and sign-up screens | `lib/auth/guard.ts`, `lib/auth/session.ts`, `components/auth/` | They need a cookie store, a database or a browser | A break there is only caught by manual checks until end-to-end tests exist | Cover with end-to-end tests later in M3 (E1 and E2 in the [quality strategy](quality-strategy.md)) | NFR-004 |
| TD-07 | Pages other than sign-in and sign-up read sample data (Closed 16 October 2026) | `lib/mock/data.ts` (deleted) | The routes were built slice by slice | None now: the requester, staff and manager pages all read the database | Done: every page was moved to real queries and the mock file was deleted with the staff slice | RTM UI Reference |
| TD-08 | `SESSION_SECRET` is only checked for length | `lib/auth/session.ts` | Keeps the check simple | The placeholder from `.env.example` would be accepted if copied unchanged | Reject the placeholder value in production or before the staging deploy | R-13 |
| TD-09 | Sign-in and sign-up redirect with a full page reload | `components/auth/LoginForm.tsx`, `RegisterForm.tsx`, `components/layout/Header.tsx` | The root layout must re-read the new session cookie, and a client-side redirect showed a stale signed-out header | Slightly slower page change after sign-in; a lint rule is switched off on the redirect lines because the full page reload is intended | Replace with a router refresh once the layout reads the session in a way that updates | n/a |
| TD-10 | Queue search, filter and sort and the staff workspace screen have no automated test | `components/staff/QueueView.tsx`, `QueueTabs.tsx`, `RequestWorkspace.tsx` and the queue pages | They are client components and need a browser or component test setup | A break in filtering, the queue tabs or the unassign button is only found by manual checks | Cover with end-to-end tests later in M3 (E1 and E2 in the [quality strategy](quality-strategy.md)) | FR-004, FR-005 |
| TD-11 | The audit log page shows only the newest 200 entries | `lib/db/queries/audit.ts` (`listAudit` limit) | Enough for the project's data volume and keeps the page fast | Older entries cannot be seen on screen (they are still stored) | Add paging or a date filter when the log grows | FR-008 |
| TD-12 | Any staff member can change the status of any request, not only their own | `lib/requests/service.ts` (`advanceRequest`) | FR-006 does not limit who updates a request, and managers close resolved work | A staff member could move a colleague's request forward by mistake (the change is audited) | Limit status changes to the assignee, managers and admins if the team asks for it | FR-006, FR-008 |
| TD-13 | Unassign has no confirmation step and discards the In progress step | `components/staff/RequestWorkspace.tsx`, `lib/requests/service.ts` | Keeps the flow short; the action is audited and the request can be assigned again | A mis-click sends in-progress work back to Submitted | Add a confirmation step if it causes problems | CR-012 |
| TD-14 | Tracking ID collisions are not retried | `lib/db/queries/requests.ts` (`newTrackingId`, `createRequest`) | 32^6 combinations make a clash very unlikely and the unique index keeps the data safe | In the rare clash the submission fails with a server error and has to be sent again | Retry with a new ID when the unique index rejects one | FR-001 |
| TD-15 | The CI gate does not yet block skipped tests or committed secrets and keeps no saved test evidence | `.github/workflows/ci.yml` | The gate was defined in the quality strategy first; the workflow change is a separate pull request | A skipped risk test or a committed secret would not stop a merge, and a run's results disappear when GitHub expires its logs | Add the skipped-test guard, the secrets scan and the artifact upload (checks 6 to 8 in the [quality strategy](quality-strategy.md)) | R-12, R-14 |
