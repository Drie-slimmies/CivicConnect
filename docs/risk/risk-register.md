# Risk Register

These are the project specific risks we've identified so far for
CivicConnect. Each one has a real cause and not just a vague label, so
the team can act on it.

## Status notes (13 October 2026, authentication branch)

- **R-13:** the mitigation is implemented and tested. Passwords are hashed with scrypt and never returned; the session is a signed HTTP-only cookie that expires after 8 hours; sign-up always sets the role to requester on the server; the role is read from the database on each request; an unknown email and a wrong password get the same response. 25 automated tests (tests/unit/auth, tests/api/auth) cover wrong password, no session, wrong role, role injection, duplicate email and short password. The pull request review against NFR-004 is still to be done. Residual risk accepted for now: there is no login rate limiting or lockout (TD-01) and no way to revoke one session, so a stolen cookie works until it expires or the signing secret is rotated (TD-02).
- **R-05:** stays open. Access control exists, but each request-data route must still call `requireRole()` and have a test before real personal data is used.
- **R-01:** reduced in practice. Vitest is installed, 39 tests run with `npm test`, and the CI workflow runs them on every pull request.
- Related decision: [ADR-06](../decisions/0009-signed-cookie-sessions-with-jose.md). Related debt: [technical debt register](../quality/technical-debt-register.md).

## Status notes (16 October 2026, staff branch)

- **R-10:** the mitigation is implemented and tested. Every staff action updates with a version check, answers 409 when the version is stale and saves nothing, and the screen tells the user to reload. Unit tests cover the stale version for assign, unassign and status changes; the 409 answer is covered in the API tests. Not yet checked with two real browsers against Neon.
- **R-05:** probability reduced. Every request-data route (requester, staff and manager) now calls `requireRole()` and has a test for 401 and 403. Keep it open until the NFR-004 review is done and real personal data is not used before then.
- **R-01:** reduced further. 90 automated tests in 14 files run with `npm test` and in CI.
- New debt for the staff slice: TD-10 to TD-14 in the [technical debt register](../quality/technical-debt-register.md).

## Status notes (16 October 2026, quality strategy)

- **Link to the quality risks:** the five quality risks in the [quality strategy](../quality/quality-strategy.md) map to this register: Q1 to R-05 and R-13, Q2 to R-05, Q3 to R-04, Q5 to R-10. Q4 (audit trail) has no separate entry; its residual gap, that a database owner could drop the immutability trigger, is recorded in the [data and persistence baseline](../architecture/data-persistence-baseline.md).
- **R-10:** probability stays Low. The strategy rates the quality risk Low to medium because the staff share one queue; revisit after a two-session check against Neon.
- **R-01:** reduced further. The CI gate now has written rules and thresholds, and the 184 tests run in it.
- **R-14:** new. The hand-run evidence (A4, E1, E2, P1) is the only evidence against the real database and a browser, so skipping it would leave Q1 and Q4 proven against a mock only.
- **R-07:** the risk showed up in the P1 run (16 October 2026): the all-requests list had a 95th percentile of 2067 ms against the 2 second goal on a free-tier Neon branch ([evidence](../quality/evidence/p1-performance-run.md)). Likelihood is now treated as realised for that page; see TD-16 for the follow-up.
