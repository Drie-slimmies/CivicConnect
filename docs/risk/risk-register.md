# Risk Register

These are the project specific risks we've identified so far for
CivicConnect. Each one has a real cause and not just a vague label, so
the team can act on it.

| ID   | Risk                                                                                            | Cause                                                                                        | Probability | Impact | Mitigation                                                                                                       | Contingency                                                                              |
|------|-------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------|-------------|--------|------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------|
| R-01 | Team lack of experience with automated testing/CI tools                                         | Earlier modules focused on manual testing, not automated pipelines                           | Medium      | Medium | Research and try a small proof=of=concept before M3, not the day it is due                                       | Reduce automated test scope and rely more on documented manual test evidence             |
| R-02 | A milestone's scope gets underestimated (No slack)                                              | All four milestone deadlines are fixed by the module schedule                                | Medium      | High   | Keep scope conservative for each milestone, treat extra features as optional, not committed                      | Cut non-essential scope rather than cut testing or security work                         |
| R-03 | The two-reviewer Pull request rule becomes hard to keep up with busy schedules                  | Limited overlapping availability between the three of us                                     | Low         | Medium | Agree on turnaround time for reviews in our working agreement                                                    | Flag it to the lecturer early if reviews are genuinely blocking progress near a deadline |
| R-04 | A requirement gets misunderstood and built differently than intended                            | Three People interpreting the same stakeholder need without a shared checkpoint              | Medium      | High   | Attach acceptance criteria to every important requirement and keep the RTM current                               | Raise it as a controlled change if it's caught after implementation has started.         |
| R-05 | Sensitive service request info gets exposed before access control is built                      | Login/role-based access control (FEC-03) isn't designed yet                                  | Low-Medium  | High   | Only use dummy/sample data until access control exists                                                           | Restrict or remove exposed data immediately if this happens                              |
| R-06 | AI-assisted work gets accepted without enough checking, and a defect or security issue slips in | Time pressure near deadline tempts the team to skip proper verification                      | Medium      | Medium | Apply the same PR/review process to AI-assisted changes as to anything else, and log it in the AI usage register | Revert or rework the change once the issue is found                                      |
| R-07 | Neon free-tier cold start breaches NFR-001                                                      | Neon scales the database to zero after 5 minutes idle                                        | Medium      | Medium | Document the limitation; ping/warm the DB before demos                                                           | Move to a paid tier if it breaches NFR-001 in practice                                   |
| R-08 | Neon free-tier compute (100 CU-hours/month) runs out                                            | Free tier has a fixed monthly compute cap                                                    | Low         | High   | Monitor usage on Neon's dashboard                                                                                | Throttle non-critical background work; escalate to the lecturer if blocking              |
| R-09 | WebSocket Pool driver exhausts connections in serverless functions                              | Neon's Pool driver holds connections differently than a typical stateless HTTP call          | Medium      | Medium | Follow Neon's serverless connection guidance; reuse the pooled client per invocation                             | Fall back to the neon-http driver for read-only paths if this recurs                     |
| R-10 | Concurrent status updates on the same ticket conflict (FR-006/FR-008)                           | Two staff members update the same ticket at once; optimistic-concurrency version check fails | Low         | Medium | Return a clear conflict error and require a reload before retry                                                  | Add retry-with-backoff if conflicts become frequent                                      |
| R-11 | POPIA encryption / least-privilege DB role is misconfigured                                     | New NFR-004 control (CR-005) not yet implemented or reviewed                                 | Low         | High   | Code review and an NFR-004 acceptance test before any real personal data is used                                 | Restrict or rotate credentials immediately if exposure is suspected                      |
