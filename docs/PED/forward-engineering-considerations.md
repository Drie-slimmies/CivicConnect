# Forward Engineering Considerations

| ID     | Concern (Now)                                                       | Why it matters now                                                                                              | Later decision/activity it influences            | Information still missing                                                              | Risk if ignored                                                                                                        |
|--------|---------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------|--------------------------------------------------|----------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------|
| FEC-01 | Deployment/hosting environment                                      | The requirements baseline should not assume a specific hosting model before compatibility is checked            | Architecture and technology-stack selection (M2) | What hosting options can we afford/use.                                                | Using possibly incompatible or expensive technology could cause late and expensive reworks.                            |
| FEC-02 | Data persistence, backup and recovery.                              | The service requests are the whole point of the system and losing them defeats the purpose of building it.      | Database design and recovery approach (M2/3)     | How much data we're realistically dealing with, and how quickly we need to recover it. | A data-loss incident could wipe out the record CivicConnect exists to keep.                                            |
| FEC-03 | Login and access control                                            | Requesters, staff and management all need different access, and some request info might be sensitive            | Security design and permissions (M2)             | Exactly what each role should be allowed to do                                         | Adding proper access control after we've already built the system is far more work than designing it in from the start |
| FEC-04 | How the system copes with several people using it at once           | We don't know real usage numbers yet, but the system still needs to hold up when more than one person           | Architecture and infrastructure choice (M2)      | A realistic estimate of how many people would use it at the same time                  | Picking an architecture without thinking about this could force a redesign once real usage start                       |
| FEC-05 | Knowing when something breaks (monitoring/logging)                  | The whole idea of CivicConnect is fixing the fact that nobody currently knows a request has stalled.            | Logging/Monitoring design (M3)                   | What counts as "broken" for this system                                                | We could end up with a system that's broken and nobody on the team would know                                          |
| FEC-06 | Keeping the codebase testable and easy to build automatically later | Decisions we make now about how the repo is organized affect how easily we can add automated tests/builds in M2 | CI pipeline setup (M3)                           | What kind of tests make sense for the stack we end up choosing.                        | Ignoring this now creates technical debt that's expensive to fix later                                                 |
